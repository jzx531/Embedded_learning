## 3. 第二个项目重点追问：时钟同步与多传感器采集

这一节包含你刚才咨询的 GPS 信号产生、卫星时钟、板子与 GPS 同步及系统用途，也覆盖简历中每条主要工作的潜在追问。

### 03. 你的同步板到底解决什么问题？

**回答主线：**不同传感器各自运行时，采集起点和频率存在差异，时间误差会积累。同步板用本地 OCXO 建立共同时间轴，参考可用时跟随外部 PPS，再向相机、深度相机和激光雷达输出所需信号。

系统输出包括多路秒脉冲、10 Hz 相机触发、Gemini 同步信号及 MID360 配套时间报文。它负责时间基准和触发控制，没有直接完成图像识别、点云配准或 SLAM。

**面试官可能继续问：**如果传感器实际曝光、扫描和时间戳对应的时刻不同，仅把输入脉冲对齐够不够？答案是不够，还要确认各设备内部时序和数据时间标签。

### 04. GPS 信号是怎么产生的？

GPS 卫星用原子钟提供稳定的时间与频率基准，生成测距码和导航电文，再调制到射频载波发射。地面接收机通过天线接收射频，跟踪卫星信号，通过码相关等方法获取测距信息，结合星历和卫星时钟修正解算位置与本地时钟偏差。

信号从卫星到地面需要几十毫秒，接收机必须处理传播时延、卫星钟差和大气等影响，不能把信号到达时刻直接当整秒。

普通位置未知的接收机通常至少需要四颗卫星求解三维位置和接收机钟差；固定位置的专用授时模式可以使用不同约束，不能把“四星”说成所有授时方式的绝对要求。

### 05. 卫星时钟是多少？10 MHz、10.23 MHz、1 Hz 是什么关系？

先确认面试官问的是时钟类型、信号频率还是时间尺度：

| 概念 | 正确解释 |
|---|---|
| 卫星的钟 | 使用原子钟，GPS 不同卫星型号的配置不同，常见铷钟、铯钟 |
| GPS 基本频率 | 信号设计以 10.23 MHz 为基本频率 |
| GPS L1 载波 | 标称 1575.42 MHz，为 10.23 MHz 的 154 倍 |
| 传统 L1 C/A 码 | 1.023 Mchip/s，码周期 1 ms；不是 1 Hz 秒脉冲 |
| 授时设备的 10 MHz 输出 | 本地设备提供的频率参考，不能混称为天线直接接收的 GPS 载波 |
| PPS | 地面接收机生成的每秒脉冲，提供秒边界 |
| GPS 时间与 UTC | 不同时间尺度，存在需处理的整数秒关系；年月日和秒号需配套时间信息 |

卫星钟也有误差，控制系统会监测并提供修正。不要说 GPS 原子钟“绝对无误差”，也不要把接收机 PPS 的精度直接等同于卫星原子钟性能。

### 06. PPS 是通过天线直接送到你的 STM32 吗？

不是，完整链路是：

```text
卫星原子钟
    → 测距码与导航电文 → 调制后的射频信号
    → GNSS 天线与射频前端
    → GNSS 接收机跟踪与授时解算
    → 接收机硬件生成 PPS 电信号
    → 板上 PPS_IN 输入捕获
    → 本地时基校准 → 多传感器同步输出
```

你的板子不负责 GNSS 射频接收和定位解算。此前使用的 TM4313 属于前面的 GNSS 授时参考设备；它输出的 PPS 才是板子的输入。

要进一步确认设备 PPS 配置的时间尺度、有效状态、脉冲极性、电平和线缆延迟，不能只看到“有 1 Hz 方波”就认为参考有效。

### 07. 板子具体如何与 GPS 同步？

本地 OCXO 输出标称 10 MHz，经 STM32 时钟树建立定时器时钟；主定时器产生本地秒周期，同时捕获外部 PPS 到来时的计数值。

首次外部 PPS 到达时，工程做一次粗相位对齐，同步相关定时器，并估算中断路径延迟进行预补偿。之后使用相位误差运行 PI，调节 DAC1220 输出，改变 OCXO 调谐电压，逐渐修正本地频率与相位。

关键是后续通过微调频率追回相位，不是每秒都直接重置计数器。各路输出共享这个被校准的时间轴。

**可画在白板上的闭环：**

```text
外部 PPS ──┐
           ├→ 相位误差 → PI → DAC → OCXO → 本地定时器 → 本地 PPS
本地 PPS ──┘                              ↑                  │
                                          └── 共同时间基准 ──┘
```

### 08. 频率同步和相位同步有什么区别？

频率一致表示时钟走得一样快，相位一致表示秒边界在时间上对齐。两个 1 Hz 信号可以周期相同，却始终相差 100 ms；也可以某一秒刚好对齐，之后因频偏逐渐分开。

对本地与参考边界定义一致的相位误差，误差随时间的斜率可反映相对频偏。例如持续 1 ppm 的频偏，约积累 1 μs/s 的时间误差，一小时约 3.6 ms。

计算时先统一正负号；误差在秒周期边界回卷时需要正确处理，不能直接拿接近一秒的计数差当作突然的大频偏。

### 09. 简历写 ns 级分辨率，能证明 ns 级同步精度吗？

不能。当前名义 280 MHz 定时器时钟对应约 3.57 ns/tick，这说明计数的时间量化步长。

同步准确度还受到参考 PPS 抖动、输入同步和电路延迟、线缆延迟、OCXO 噪声、DAC 调节、闭环残余误差和测量设备误差影响。

建议回答：

> 简历写的是 ns 级计数分辨率，不是已经测得的 ns 级绝对同步准确度。实际同步误差需要用独立仪器在板端和传感器端测量，再报告统计分布和测试条件。

不要拿软件 `LOCKED` 状态或计数频率代替精度实测。

### 10. 输入捕获为什么比中断里读取当前计数值更可靠？首次延迟补偿是否完美？

输入捕获在外部边沿到达时由硬件锁存计数，CPU 稍晚进入 ISR，不会直接把这段响应延迟加到已锁存的捕获时刻。

但首次粗对齐是由中断路径触发操作，仍涉及响应和执行耗时。当前工程利用捕获值与当前计数的差等信息估算延迟，做预推进补偿。

这种方法不意味着所有输出物理边沿都被精确移动到过去的外部边沿。主从触发传播、GPIO 和板级通路，以及已发生的输出瞬态，都要考虑；应通过测量标定残余偏差。

### 11. 你的 PI 控制公式是什么？为什么 DAC 能改变时间？

以代码使用的有符号相位误差 `e[k]` 为输入，简化表示为：

```text
I_candidate[k] = clamp(I[k-1] + e_ctrl[k], integral_limit)
P_code[k] = trunc(e_ctrl[k] / P_divisor)
I_code[k] = trunc(I[k]      / I_divisor)
target[k] = nominal_code - direction × (P_code[k] + I_code[k])
```

每个有效 PPS 样本更新一次，名义采样周期约一秒。实际还包含误差限幅、死区、候选积分是否接受、DAC 范围和单次步长限制。

P 项对当前偏差作出响应，I 项积累持续误差，使调谐量能抵消长期残余频偏。DAC 改变 OCXO 的频率，频率差随时间积累成相位变化，因此能逐渐追回时间偏差。

当前目标码以标称中心码为基准计算，不应误讲成“每秒都把完整 P+I 再累加到上次 DAC 上”。调谐方向必须由实物确认。

### 12. P、I 的除数都为 2800，是否意味着两个增益相同？

不能直接这样说。P 的输入是当前相位误差，I 的输入是多次相位误差的累积，两者的作用、量纲和时间效应不同。采样周期也会影响离散积分的实际增益。

整数除法会截断，不足一个 code 的比例修正可能为零；积分仍可跨多个样本积累。若相位误差位于死区，代码把本次控制误差设为零，已有积分状态不会因此自动清空。

除数变小一般意味着对应作用更强，但闭环稳定性还受 OCXO 调谐灵敏度、时钟积分特性和更新延迟影响。

### 13. 你怎么调 PI？积分饱和为什么会出问题？

先测 DAC 增减时频率变化方向、每 code 对应频率变化、预热及环境影响，再调闭环。建议从小扰动和较弱控制开始，检查收敛时间、超调、稳态误差和 DAC 抖动。

I 太强可能导致振荡和追赶参考噪声；太弱会收敛慢。执行器到边界后，继续累加积分可能让恢复时长时间无法退出饱和。

当前实现有积分限幅和条件积分：候选积分若会进一步加深饱和，本次不接受；反向误差仍可推动积分回退。它与输出步长限制是不同保护。

**不要说：**“调到日志变 LOCKED 就完成了。”还应测试持续运行、参考丢失、参考切换和温度变化。

### 14. 为什么实现四种驯服算法？哪种最好？

| 算法 | 思路 | 适合讨论的取舍 |
|---|---|---|
| 相位 PI | 每个有效 PPS 根据相位误差及积分调节 | 响应与噪声抑制需折中，依赖调谐标定 |
| 双窗口 | 用短窗口捕获、长窗口跟踪相位变化趋势 | 可兼顾捕获与稳定，需要设计切换条件 |
| 相位斜率 | 长窗口估计频偏，小步修正 | 更重视长期趋势，响应较慢 |
| 分级步进 | 根据估计频偏选择不同码值步长 | 便于方向确认与初步调试，平滑性依赖规则 |

当前代码默认选择相位 PI，四种算法可以选择，不是同时运行。代码存在不代表四种算法都完成同条件长期实测，也不能无数据地宣称某种最好。

若面试官追问比较，应给出固定参考、预热条件和扰动下的收敛、抖动、保持及调谐动作对照；没有做过就明确说明。

### 15. 你如何判断锁定？为什么需要回差和连续计数？

当前源码使用相位误差门限和连续样本：进入锁定与退出锁定使用不同门限，并要求持续满足一定次数，避免在噪声下反复切换。

当前配置是连续 8 次误差不超过 1 μs 进入锁定；锁定后连续 3 次超过 10 μs 退出。面试不必主动背数字，但应能从代码解释它们。

该状态表示“满足软件判据”，不等于每个样本都在 1 μs 内，也不等于已验证频率稳定度或外部参考本身正确。还应看误差曲线、参考有效性和仪器结果。

### 16. 没有 PPS_IN 能否输出？曾锁定后参考消失怎么办？

可以继续输出。输出由本地 OCXO 和定时器生成，不是外部 PPS 的逐个转发。

- 从未有参考：属于自由运行，各路维持设定的相对时序，但绝对时间和长期频率由本地振荡器决定。
- 曾有参考后丢失：进入保持运行，保留最近调谐值，OCXO 继续提供时基。

当前保持并不是基于温度和老化模型预测的高阶 holdover。多久偏离多少必须实测；“脉冲还在”不等于“还与 GPS 对齐”。

### 17. 为什么换参考后可能锁不住？CDA-2990 Internal 模式能证明是 GPS 参考吗？

不能。先查参考设备手册、工作模式和实际输出端口；只接电、选择 Internal，不能据此断言其 PPS 是否启用，更不能证明它已经 GNSS 驯服。

排查顺序：

1. 示波器确认实际输出幅值、极性、周期、脉宽、抖动和地线。
2. 查看参考自身锁定状态、时间尺度和 PPS 有效设置。
3. 看 MCU 捕获序号是否持续推进、是否溢捕获或超时。
4. 看相位误差斜率、DAC 是否持续向边界、调谐范围是否足够。
5. 参考确认有效后，再讨论是否需要更快的捕获或重新粗对齐。

独立自由运行参考也可能被另一个振荡器跟踪，但它不是绝对标准，频偏、漂移和噪声也可能超出当前闭环适用范围。此前更换参考失败的具体根因，不能仅凭型号或一段日志下结论。

### 18. PPS 已锁定，MID360 时间就一定是真实 UTC 吗？NMEA RMC 起什么作用？

不一定。PPS 提供秒边界，RMC 提供日期和时间标签，设备需要按自身协议把二者关联起来。串口字节到达时刻不是高精度秒边沿。

当前 `main.c` 启动时将时间设为 2026-01-01 00:00:00；存在串口 `TIME=...` 设置接口，但普通上位机设置本身不自动证明与 GNSS 秒号精确配对。工程未凭一个 PPS 自动得到真实日期。

正式验证要确认：报文指的是当前还是下一 PPS、UTC/GPS/本地时间尺度、校验和、报文有效标记、串口发送时序，以及雷达实际接受的同步类型和状态。不能只看格式正确或 DMA 发送成功。

### 19. 为什么相机通道用输出比较，不直接用普通 PWM？

当前相机触发与 1 Hz PPS 共用主定时器计数周期。普通 PWM 通道共享同一组计数器和周期，不能仅给其中一个普通通道单独设置 10 Hz 周期。

所以相机通道使用输出比较翻转，在硬件比较命中时改变输出电平，由回调安排下一个边沿，形成 10 Hz 波形。

可选替代方案是独立的同步 PWM 定时器或 DMA 更新比较值，但要看引脚复用、路由和软件复杂度。不能概括成“PWM 不准确，输出比较才准确”，两者都能由硬件产生边沿。

### 20. 比较中断会被别的通道覆盖吗？如果中断太晚怎么办？

当前检查没有发现其他通道正常处理会直接覆盖比较中断标志；不同通道有独立标志位。

更值得关注的是比较值更新期限：边沿已由硬件产生，但软件必须及时安排下一边沿。如果写入的目标计数值已被计数器越过，下一次命中可能要等回卷，形成异常长脉冲或长空隙。

当前源配置高电平 4 ms，下一边沿安排不能拖过相应期限。这个值是排障背景，简历不必写。可增加最大 ISR 延迟、迟到计数、当前计数与目标比较值差、异常恢复日志；这些是后续建议，不表示已经实现。

一次中断标志也不是无限事件队列，长时间无法服务时可能丢失事件计数。

### 21. 相机 MODE、SYNC、STB 是怎么配合的？为什么万用表读数很低？

当前相机文档和代码对应关系：

| 信号 | 作用 | 应核对的事实 |
|---|---|---|
| MODE | 选择工作模式 | PE15 在 GPIO 初始化后置高；相机 MODE 高时强制硬件触发，Backlight 设置无效 |
| SYNC | 实际触发输入 | PB10 输出 10 Hz；板端源配置高 4 ms，相机端要求高脉宽至少 3 ms |
| STB | 相机输出的曝光/闪光相关信号 | 可辅助观察相机响应，需按文档解释其与曝光的关系 |

相机 MODE 是 3.3 V 基准，SYNC/STRB 是 1.8 V 基准，需核对电平转换、方向和共地。MODE 上电前或 GPIO 初始化前的状态不能仅靠后续软件配置保证。

3.3 V、4% 占空比波形的理想平均值约 0.132 V，万用表直流档读数很低不代表没有脉冲；要用示波器测幅值和时序。若真是持续 0 V，则还要查运行阶段、接线和负载。

### 22. 相机几秒后冻结，怎么证明问题在哪？

同时记录：相机端 SYNC、MODE、STB，V4L2 出帧序号/时间戳/超时，USB 内核日志，应用缓冲归还情况，以及后续编码和渲染计数。

先找第一处停止推进的环节。同步脉冲仍有，不代表曝光、USB 出帧和应用处理都正常；V4L2 `select timeout` 也不能单独证明是同步板故障。

之前测试提过约 50 ms 高/50 ms 低，与当前源配置的 4 ms 高/96 ms 低不一致，应先核对烧录版本、采样方法和测点。当前 MODE 已在代码中改高，但此前冻结问题没有由这次改动自动得到根因确认。

### 23. 硬件同步、时间戳对齐和真正同时采样有什么区别？

- 硬件同步：给设备共同参考或触发事件。
- 时间戳对齐：确保数据携带的时间对应同一时钟域，且记录时刻语义明确。
- 同时采样：真实曝光、扫描点采样等物理事件在目标误差范围内发生。

三者有关联但不能互相替代。相机触发到曝光可能有固定延迟和抖动；扫描式雷达一帧里的点也不是同时产生。

只把收到图像时的 `ros::Time::now()` 写进去，会包含传输和调度延迟；把最近一帧雷达时间直接贴到相机帧上，没有触发序号和队列关联，也可能配错帧。

### 24. 你会如何证明这套同步系统有效？

分三层验证：

1. **板级：**同一仪器测 PPS_IN 与各输出边沿，记录固定偏差、分位数、峰峰值、周期和异常间隔；确认仪器与探头误差。
2. **传感器级：**确认设备接收同步、时间戳语义、帧号和触发关系；测真实曝光/扫描相关信号及端到端时间标签。
3. **应用级：**在静态和运动场景比较相机雷达投影误差、运动畸变和重复性，并控制外参、场景和算法配置。

长测要记录参考型号与锁定状态、预热、环境、固件版本、采样时长、丢样和失锁事件。可准备误差与 DAC 变化曲线，但不要把旧文档中单次试验结果当作当前版本已经重新验证的指标。

## 4. 第一个项目追问：RFSoC 通感一体化

### 25. 这个项目与激光雷达岗位有什么联系？

联系在传感器信号处理、时间频率误差、实时数据链路和软硬件协同；无线电通感平台与光学雷达在传播、发射接收结构和处理链上存在差异。

可迁移的是分析和工程方法，不能因为都涉及“感知”就声称已经做过激光雷达点云算法。应准备自己的完整信号流程图和负责模块。

### 26. 为什么用 OFDM？怎么从信号得到距离和角度？

OFDM 在多个子载波上传输信息，在已知或可估计符号条件下，可利用回波相对参考信号的频域相位变化估计时延；阵列通道间的相位关系用于角度估计。具体算法应按你项目的实现说明。

单基地、常见理想模型下距离与往返时延满足 `R=cτ/2`，距离分辨率量级为 `c/(2B)`。不要把载频直接当作距离分辨率决定因素；角分辨率还与波长、阵列孔径和估计方法有关。

追问常包括频偏、相位噪声、收发泄漏、直达径、多径和阵列通道幅相一致性。

### 27. 为什么把算法放 FPGA？哪些放 PS 或上位机？

按吞吐、并行性、确定性、开发成本划分：规则的大吞吐流水线适合 PL，控制与配置适合 PS，复杂可变算法、可视化和离线分析可以先放上位机。

准备一个实际模块讲资源、位宽、流水线延迟和数据接口。若用了定点化，需要解释溢出、舍入、量化误差以及与浮点参考的对比，不能只说“FPGA 比 CPU 快”。

### 28. 你写了 100G 光口，如何证明真的达到相应吞吐？

先区分端口线速、协议负载吞吐、主机接收吞吐和算法处理吞吐。100 Gbit/s 的字节换算上限约 12.5 GB/s，实际有效数据还受协议及实现开销影响。

应讲清网卡、收发端、帧长、数据格式、持续时长、包序号、丢包率、CPU/内存带宽及测试工具。不能把链路协商到 100G 当作应用实测 100G。

简历中高速光口和 PS 端 lwIP/RJ45 控制链路应分开画，避免让人误解成 PS lwIP 承担了全部 100G 数据处理。

### 29. 乒乓缓冲和共享内存怎么保证正确？

两块缓冲交替填充和处理，可以重叠生产消费，但必须有明确的所有权、长度、序号和状态。生产者不能覆盖消费者正在读的数据。

消费者跟不上时，需要有界队列和丢弃/背压策略；共享内存减少部分拷贝，但不自动解决进程同步、内存可见性和异常退出恢复。

如涉及 DMA/AXI 与 CPU 缓存，还要说明平台的一致性机制、缓冲分配和必要的 cache 维护。具体细节以你使用的裸机或 Linux 环境为准。

### 30. 这个项目你独立做了什么？如何评价感知结果？

按模块列出你实际完成、协作完成和参考复用的内容，用设计文件、代码、实验记录支撑。不要把团队整机能力都说成个人实现。

感知性能可讨论距离/角度误差、分辨能力、检测表现、处理耗时及不同条件下的稳定性；没有真值就不能只凭图像“看起来像目标”宣称精度。

## 5. 第三个项目追问：C++ 工程能力

### 31. Reactor 如何工作，为什么适合多路 I/O？

核心是事件循环等待就绪事件，把对应连接交给处理逻辑；是否配线程池、每个线程是否有独立 loop，要按你实现说明。

`epoll` 告诉应用 I/O 就绪，不代表业务处理已经完成。耗时任务不能无限阻塞 loop。追问可能涉及 LT/ET、非阻塞读写、短读短写、EAGAIN 和连接关闭。

### 32. 多线程队列、连接对象和资源释放怎么管理？

明确谁拥有对象、任务结束后谁释放、关闭时如何取消并等待。RAII 管理资源，智能指针解决部分生命周期问题，但不会自动消除数据竞争和循环引用。

如果消费者慢，不能无限堆队列；如果回调捕获裸指针，必须证明对象生命周期。面试官会让你将这些思路迁移到图像与点云缓冲。

### 33. “性能优化显著提高效率”具体提高了多少？

准备优化前后的固定测试条件：请求类型、并发、连接复用、TLS、线程数、机器资源、吞吐、延迟分布和错误率。

没有可靠数据时，解释具体减少了什么开销、如何验证，避免临时编造提升百分比。平均 QPS 不是唯一指标，P99 延迟与过载退化也重要。

### 34. 这段经历怎么用于禾赛的数据处理任务？

可以迁移到数据读取、任务调度、有界队列、资源管理、日志与可视化服务。点云任务还要考虑连续内存、拷贝成本、邻域搜索和计算开销，不能直接照搬网络请求的线程数配置。

业务重点应转到处理正确性、帧间时序、点数规模和吞吐，而不是把 HTTP 服务作为点云算法能力的替代证据。

## 6. JD 中最需要补的点云、RGB-D 与定位知识

### 35. 激光雷达如何测距？噪点通常从哪里来？

常见脉冲 ToF 系统测往返时间，理想模型 `d=cΔt/2`；其他技术路线不能全部用这一句话概括。

噪点和误差可能来自背景光、低信噪比、低/高反射率、混合像素、多径、雨雾粉尘、串扰、设备参数和运动。要区分随机噪声、系统偏差、动态目标和边缘结构。

不要把自己板子的 PPS 计数分辨率当成雷达测距分辨率，它们属于不同测量链路。也不能默认禾赛所有产品都采用与你假设完全相同的实现。

### 36. SOR 和 ROR 点云滤噪分别怎么做？

SOR：统计每点到邻近点的平均距离，再按总体分布构造判据，删除平均邻域距离明显异常的点。常见参数是邻居数和标准差倍率。

ROR：统计一定半径内的邻居数量，删除邻域支持不足的点。参数是搜索半径和所需邻居数。

两者都可能误删稀疏远距离目标、边缘或细杆。固定阈值不一定适合随距离变化的点密度；应分距离和目标类型评估，必要时采用自适应参数或传感器结构信息。

**可能让你手写：**最朴素实现如何做、邻域搜索复杂度如何降低、如何保留原始索引和被删除点以便复核。

### 37. 体素降采样是不是滤噪？体素大小怎么选？

体素降采样将空间划分网格，每格用代表点等方式减少点数，主要解决数据量和密度问题；不保证清除所有离群点。

体素过大会丢失细节、混合表面，过小则减负有限。应按距离单位、目标尺寸、配准尺度和耗时预算选择，并观察几何边界和下游效果。

降采样后法向量、强度、颜色和语义标签的聚合需要定义规则，不能对类别 ID 随意求平均。

### 38. SLAM 的基本结构是什么？前端和后端各做什么？

SLAM 同时估计位姿并建立地图。前端处理数据关联、跟踪和局部运动估计；后端基于约束做优化，可能包含局部优化、位姿图与回环修正。

还要理解初始化、地图管理、动态目标、退化检测和重定位。只有帧间 ICP 并不等于完整 SLAM，也不能把“点云显示在 RViz”当作建图定位算法已经完成。

与你最相关的切入点是：时间、坐标系和采集质量不正确，会让前端残差变大，后端优化不能无条件修复错误输入。

### 39. ICP 的步骤和目标函数是什么？

给定初始刚体变换，交替执行建立对应关系与优化变换，直到达到停止条件。

点到点形式：

```text
min over R,t: Σ ||R p_i + t - q_i||²
约束：R 是合法旋转矩阵
```

前提是有足够重叠、可用初值和有意义的对应。ICP 属于局部优化，初值差、重复结构、动态目标和低重叠会导致错误结果。

可使用多尺度处理、合理的对应距离、剔除异常对应或鲁棒核改善，但没有一个参数能保证所有场景收敛。

### 40. 点到面 ICP 与点到点有什么区别？为什么平面会退化？

点到面形式：

```text
r_i = n_iᵀ (R p_i + t - q_i)
min over R,t: Σ r_i²
```

它最小化沿目标法向的偏差，通常需要可靠法向和适当初值。平面场景对某些运动方向的约束较弱，例如单一大平面难以充分约束平面内平移和绕法向旋转。

不能看到残差小就认为所有自由度都准确，应结合几何分布、可观测性和独立真值。鲁棒核能降低异常点影响，但不能凭空补回不存在的几何约束。

### 41. KD-tree 为什么有用？法向量怎样估计？

KD-tree 等空间索引用于加速最近邻或半径查询，避免对每个点都扫描所有点；查询性能受维度、分布和索引构建方式影响，不能笼统保证任意情况都是 O(log N)。

法向量常通过邻域点的协方差矩阵/PCA 估计，最小特征值对应的方向作为局部法向估计。邻域太小易受噪声影响，太大会跨越边界；法向正负方向还需要一致性约定。

### 42. 相机、雷达、IMU 坐标系如何转换？

明确约定 `T_CL` 表示从雷达系 L 到相机系 C：

```text
p_C = R_CL p_L + t_CL
T_CL = [ R_CL  t_CL ]
       [  0      1  ]

T_LC = inverse(T_CL)
R_LC = transpose(R_CL)
t_LC = -transpose(R_CL) × t_CL
```

旋转矩阵应满足正交性及行列式为 +1。齐次变换链必须按坐标定义相乘，不能只凭变量名猜。

单位、左右手系、轴方向、角度制/弧度制、四元数分量顺序，都是常见错误来源。ROS 消息中的 `frame_id` 和 TF 也必须与数据实际坐标一致。

### 43. 内参、外参和联合标定分别是什么？怎么验证？

相机内参描述投影模型，如焦距和主点，并配套畸变模型；外参描述坐标系之间的刚体关系。相机雷达联合标定需要跨模态的几何约束，例如多个姿态标定板的平面/边缘对应。

应使用覆盖视场、距离与姿态的样本，避免只在单一位置拟合。优化中可以使用重投影、点到面或边缘等残差，具体取决于可观测特征和模型。

验证要用未参与拟合的场景，检查不同位置和距离下的误差分布与重复性。重投影误差低不自动证明所有外参都可靠，也不代表时间偏差已经消除。

### 44. 雷达点如何投影到图像？RGB-D 如何生成三维点？

先将雷达点变换到相机系，只考虑在有效视野内、`Z_C > 0` 的点。理想针孔模型：

```text
u = fx × X_C / Z_C + cx
v = fy × Y_C / Z_C + cy
```

实际需处理镜头畸变、图像是否已去畸变、缩放裁剪后的内参、遮挡，以及多点投影冲突。

若深度图存的是沿相机光轴的 Z，反投影为：

```text
X = (u-cx) × Z / fx
Y = (v-cy) × Z / fy
三维点为 (X,Y,Z)
```

有些设备输出的是沿视线的距离，不等于 Z；必须按设备定义和标定模型处理。深度值的毫米/米单位与无效值也要确认。

### 45. 什么是点云运动畸变？时间误差会造成多大影响？

扫描式雷达的一帧点云在一段时间内逐点形成，设备运动时，不同点对应不同位姿。去畸变需要逐点时间，以及 IMU/里程计等估计的连续运动，将点变换到选定参考时刻。

PPS 对齐秒边界，不能自动让一整帧点同时采样。只有帧头时间、没有逐点时间，也会限制去畸变能力。

量级估算：

```text
平移错位量 ≈ 速度 v × 时间误差 Δt
小角度旋转错位量 ≈ 距离 r × 角速度 ω × Δt
```

例如 10 m/s、10 ms 对应约 10 cm 平移；20 m 处、30°/s、10 ms，对应约 10.5 cm 的旋转错位量级。这是简化估算，不是完整场景误差模型。

静态对齐尚可、运动越快越差时，要优先检查时间偏差、曝光时刻、逐点时间与去畸变，同时也应考虑外参和机械变化。

### 46. RGB-D 深度图为什么有空洞？怎么滤波和填补？

空洞可能来自遮挡、低纹理、反射/透明表面、测量范围限制、环境光和匹配失败；原因依双目、结构光或 ToF 原理而异。

中值滤波可抑制部分脉冲噪声，双边/引导滤波等可利用邻域和图像边缘信息，时域方法可利用历史，但运动时有拖影风险。

填补不能随意跨越前景背景边界，也不应把猜出来的值标成传感器实测。保留有效掩码和置信度，分别评估有效区域误差与填补区域误差，警惕把缺测表面“补成”虚假障碍或通路。

### 47. RGB-D 定位怎么做？有哪些失败场景？

可基于 RGB 特征与深度构造三维约束，也可使用稠密几何或光度残差估计相邻帧位姿；需要数据关联、离群值处理和局部优化，完整系统还涉及地图、回环和重定位。

低纹理、快速运动、动态目标、深度缺失、重复结构和曝光变化都可能使跟踪失效。RGB 和深度若不同步或未正确对齐，融合也可能降低效果。

面试前至少能讲一种方法的输入、状态、残差、初始化和失败判断，不需要临时背所有 SLAM 系统名称。

### 48. “深度与语义结果融合”可以怎么做？

先保证时间和空间对齐，将像素语义关联到深度点，构建带语义的点云或地图；也可用深度几何约束帮助解释语义结果，具体融合层级由任务决定。

要处理遮挡、模型置信度、标定误差、无效深度、动态目标和跨帧一致性。语义标签错误可能污染地图，不能把网络输出直接当真值。

没有做过这类项目时，可解释基本管线与准备中的实验，不要把现有 PyTorch 经历扩展成已完成语义 SLAM。

### 49. 怎么评测滤噪、配准和定位算法？

| 任务 | 应关注的指标 | 容易误导的结果 |
|---|---|---|
| 点云滤噪 | 噪点检出、有效点保留、边缘/细小目标保持、分距离误差、耗时 | 删除点越多就认为越好 |
| 配准 | 有条件定义的对应误差、重叠情况、位姿误差、收敛率、耗时 | 只报告删掉大量难点后的低 RMSE |
| 定位/SLAM | ATE、RPE、跟踪成功率、漂移、地图质量与计算开销 | 靠过强轨迹对齐掩盖尺度或漂移问题 |
| 深度处理 | 有效率、深度误差、边界表现、填补置信度、时域一致性 | 提高填充率却不检查错误表面 |
| 嵌入式部署 | P50/P95/P99 耗时、吞吐、内存、队列年龄、功耗/温度 | 平均耗时低但偶发积压严重 |

ATE 是整体轨迹误差，RPE 关注选定间隔的相对运动误差；需要说明时间匹配、坐标对齐方式和真值质量。

Open3D 等库的 fitness/RMSE 取决于具体 API、阈值与对应集合。记录版本和定义，不把不同库或不同阈值下的同名数值直接比较。

### 50. 点云算法如何部署到嵌入式平台？

先明确平台是 MCU、ARM Linux SoC、GPU 还是 FPGA；你当前 STM32 板主要做时序控制，不应默认能承担整套高密度 SLAM。

先跑正确的参考实现，做性能剖析，找邻域搜索、内存访问、拷贝、分配或优化求解的瓶颈，再考虑降采样、缓存复用、并行化、SIMD/GPU 和精度取舍。

固定数据和质量指标比较部署前后差异，测试热稳态和长时间运行。降低精度与优化实现成本不同，应分别报告。

### 51. 离线评测和可视化工具应该保存什么？

至少保存输入数据标识、设备/标定/固件版本、时间戳语义、算法配置、依赖版本、输出、错误和耗时统计。

可视化应支持原始/处理后对比、被删除点着色、对应线、坐标轴、投影叠加和分距离统计；数值与图形互相验证。

不只挑好看的截图，要保留失败样本和固定测试集，避免在测试集反复调参后仍把它当独立验证集。

### 52. 相机雷达投影对不齐，怎么区分外参、时间、内参问题？

先统一时间、单位和坐标系定义，检查驱动字段及图像处理流程，再用有控制的静态/运动实验缩小范围。

- 静态场景也普遍错位：优先查内外参、畸变、变换方向、尺寸裁剪和安装。
- 静态尚可、运动时误差明显增加：查时间偏差、曝光与扫描时刻、逐点去畸变。
- 误差随图像位置或距离变化：查畸变、内参、外参以及深度尺度等，不能仅凭一种现象唯一定位。

用静态几何残差、不同运动方向和速度的测试共同验证，不能只“拖动外参直到画面看起来对上”。

## 7. C++、Linux 与现场编程补充

### 53. `volatile` 能解决多线程和中断共享数据问题吗？

不能。它不提供通用原子性、互斥或跨线程同步语义。

你的固件用短临界区取得捕获状态快照，目的是避免字段来自不同次采样；进入前保存并恢复原中断状态，不能无条件打开中断。临界区应保持短小。

C++ 线程通常使用 mutex、atomic 等同步；DMA cache 一致性又是另一层问题，不能靠加 volatile 解决。

当前同步板工程是裸机中断加主循环结构。简历中提到的 RTOS 经验需要用你实际做过的其他工作支撑，不能把本工程讲成已有任务调度、信号量和优先级反转处理的 RTOS 项目。

### 54. 生产者消费者怎么保证实时性？

使用有界队列、清晰的所有权、关闭与取消机制，统计处理速率、队列长度和最老数据年龄。

业务允许时可丢弃过期的原始图像或点云，但应保留一致的时间关联；若数据存在依赖，例如压缩视频参考链，不能随意丢包后假定下游还能正常解码。

线程越多不保证越快，CPU 过度订阅、锁争用和内存带宽都可能成为瓶颈。

### 55. ROS 时间戳、主机收包时间和硬件时间如何选择？

首先查设备和驱动文档，确认时间戳属于采样、帧起点/终点还是主机接收时刻，单位与时钟域是什么。

记录原始硬件时间，明确转换到统一时间轴的方法，再进行帧关联。`message_filters` 一类近似匹配不会自动校正设备时钟，TF 也不能修复错误时间标签。

你工作区的 LIV 参考方案含“共享最近一次雷达时间给相机”的做法，可讨论其错帧风险；它不是当前同步板已经完成全链路精准帧配对的证据。

### 56. 实时处理掉帧或内存增长，怎么定位？

按采集、处理、队列、输出分层统计帧序号与耗时；检查重复拷贝、每帧分配、资源泄漏、消费者阻塞、同步等待和 I/O。

Linux 可用 top/htop、pidstat、perf、日志及内存分析工具逐步定位。区分真实泄漏、缓存池增长和系统页缓存；一次 RSS 上升不等于泄漏。

跨设备延迟测量要处理时钟偏差，本机区间测量优先使用单调时钟。

### 57. 如果现场让你写代码，优先准备什么？

按岗位内容推测，建议准备下列练习，不是声称公司一定考这些：

| 练习 | 核心考点 | 必须测试的边界 |
|---|---|---|
| 点云体素哈希降采样 | 空间离散化、哈希、均值与索引 | 负坐标、空输入、单位、NaN、体素边界 |
| 最近时间戳配对 | 双指针/有序搜索、容差、单调性 | 缺帧、重复、乱序、时钟域不一致 |
| 三维点刚体变换与投影 | 矩阵、坐标约定、有效性判断 | Z≤0、视野外、无效深度、畸变处理 |
| 有界生产者消费者队列 | mutex/条件变量、所有权、退出 | 队列满、关闭唤醒、异常、剩余资源释放 |
| 滑动窗口均值/异常检测 | 累加、数值稳定、索引回卷 | 窗口未满、异常值、溢出 |

另外复习数组、链表、哈希、二分、堆和基本复杂度。先写对边界，再讨论 SIMD、多线程或零拷贝。

### 9.2 小实验 A：点云滤噪与配准，最值得先做

建议先用 Open3D Python 快速验证，再根据时间将关键逻辑换成 C++/PCL。语言选择是学习建议，不是截图中明示的要求。

执行顺序：

1. 准备公开示例点云或自采数据，保留原始文件；记录单位和数据来源。
2. 固定随机种子，人工注入一部分离群点，保留标签。
3. 对比体素降采样、SOR、ROR；保留删除点可视化，统计有效点误删与噪点检出。
4. 选择一帧点云生成带已知变换的副本，加入可控噪声和部分重叠，再运行 ICP。
5. 对照点到点与点到面、不同初值和阈值，计算位姿误差与耗时。
6. 用真实相邻帧再测试，明确此时可能没有独立位姿真值。

最低交付物是脚本/配置、输入说明、一张滤噪对照图、一张配准图、一张参数与误差耗时表，以及一个失败案例。

人工数据只能检验受控场景，不能替代真实雨雾、多径或复杂反射噪声。实验指标是建议测量项，不是已经实现的项目成果。

### 9.3 小实验 B：时间误差对投影的影响

有设备数据时，用已知内外参对相机雷达做投影；在保持空间标定不变的情况下，尝试可控的时间偏移，比较静态与运动片段的误差。

没有完整设备链时，可用简化运动模型做仿真：固定相机模型和静态三维点，给定平台运动，计算不同时间偏差下的投影变化。要明确它验证的是数学模型，没有证明真实系统的同步精度。

这个实验可以把你的同步板经历直接连接到 JD 中的标定、感知定位与鲁棒性，价值通常比再增加一段空泛的“系统设计”描述高。

### 9.4 面试前整理一份第二项目证据包

建议只准备几页内容，面试时按追问展开：

- 一张硬件与软件时间链路图，标清 GNSS 设备和你的板子的职责边界。
- 一张 PPS_IN、PPS_OUT、相机触发和 Gemini 信号的波形及测量条件。
- 一组同版本日志与 CSV 分析图，标明参考、预热、持续时间和异常事件。
- 一张误差定义表：分辨率、固定偏差、抖动、长期漂移和测量不确定度。
- 一项已定位问题及验证过程；未解决的问题给出下一步测量方案。

若目前只有 MCU 日志，先如实说明它能证明捕获和控制状态，不能单独证明传感器曝光精度或整个系统绝对 UTC 准确。

### 12.3 建议继续阅读的材料

以下是延伸学习入口，没有在本次逐页核验或完整复现：

- [PCL 官方教程](https://pointclouds.org/documentation/tutorials/)：优先看 VoxelGrid、StatisticalOutlierRemoval、RadiusOutlierRemoval、KD-tree、registration。
- [OpenCV 相机标定与三维重建](https://docs.opencv.org/4.x/d9/d0c/group__calib3d.html)：相机模型、畸变、calibrateCamera、solvePnP。PnP 与相机雷达联合标定不能直接混为同一任务。
- [Open3D RGB-D 图像](https://www.open3d.org/docs/release/tutorial/geometry/rgbd_image.html)：深度单位、内参和点云生成。
- [HesaiLidar 官方 GitHub](https://github.com/HesaiTechnology)：查看与实际目标设备匹配的驱动/SDK 文档，重点看点时间、同步状态、数据结构与配置，不猜测内部实现。
- [FAST-LIO](https://github.com/hku-mars/FAST_LIO)、[FAST-LIVO2](https://github.com/hku-mars/FAST-LIVO2)：用于理解雷达惯性/视觉融合管线，先理解输入、时间、外参和状态，再考虑源码细节。
- 《视觉 SLAM 十四讲》：优先补三维刚体运动、相机模型、非线性优化和前后端概念。
- 《State Estimation for Robotics》：有余力再深入状态估计与不确定度，不必面试前通读。

这些资料的推荐顺序是几何基础 → 点云滤波与 ICP → 标定和时间关联 → RGB-D/定位 → 嵌入式性能评测。先完成一个能解释、能复现的小实验，再扩展系统规模。
